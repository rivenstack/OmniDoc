Raw size is `dimensions × 4` bytes before pgvector/Postgres row and index overhead. [pgvector's official documentation](https://github.com/pgvector/pgvector#supported-types) caps `vector` at **2000 dimensions** and says mixed dimensions need model/dimension-specific indexes. The current B-06 V5 `embeddings` table has `chunk_id` as primary key and an unconstrained `vector` column: one stored model per chunk; candidate swaps require separate runs/re-embedding and query/model/dimension filtering. This is an **inference from the inspected schema**, for Architect to disposition. No production schema change is proposed here.

## Findings

### Verified law/regulation

None investigated or concluded. Provider onboarding, data transfers, sanctions/payment eligibility, and use terms require the business owner and, where needed, counsel/provider account team; a public fixture probe does not settle those issues.

### Verified provider requirements

- **API shape.** AvalAI's [embedding reference](https://docs.avalai.ir/en/api-reference/embeddings) documents `POST https://api.avalai.ir/v1/embeddings`, Bearer authorization, `model`, string or string-array `input`, optional `encoding_format` (`float` default or `base64`), optional model-dependent `dimensions`, and optional `user`. The response is an OpenAI-shaped `data[]` of float vectors with `index`, `model`, and `usage.prompt_tokens`/`total_tokens`. Error table includes 400, 401, 403, 404, 429, 500. [Rate-limit guidance](https://docs.avalai.ir/en/rate-limits) adds `x-ratelimit-*` headers and possible `Retry-After`; no endpoint-specific uptime or latency SLA was found. **Verified provider rule H**, not an interoperability test.
- **Account/cost.** [AvalAI tiers](https://docs.avalai.ir/en/rate-limits) say email-only Basic gets **25,000 tomans** signup credit, phone verification brings the total to **200,000 tomans**, Tier 2 begins after **$10 cumulative top-ups**, and top-ups are in IRT using the dashboard exchange rate. It states no monthly spend cap. The [older marketing pricing page](https://avalai.ir/pricing/) instead advertises **20,000 tomans** startup API credit: **conflict; account offer controls**. Free credit is a balance, not a free embedding model. Neither minimum cash top-up, tax treatment, package applicability, nor international payment eligibility was established. USD model prices are catalogue units, not a guaranteed IRT charge. **H** tier page; **unresolved** actual account economics.
- **Gemini billing conflict.** The [current AvalAI model page](https://docs.avalai.ir/en/models/gemini-embedding-001) says $0.15/1M input and $0 output, while AvalAI's [2025-09-18 announcement](https://docs.avalai.ir/en/news/2025-09-18-gemini-native-api-embedding-support-performance-improvements) says $0.15 input and $0.075 output. The model page's example also incorrectly uses `/v1/chat/completions` for an embedding model. Use the [dedicated embedding reference](https://docs.avalai.ir/en/api-reference/embeddings) for endpoint shape, and verify the dashboard/transaction record for actual charges before relying on the estimate. **H** documented conflict / **unresolved** bill.
- **Key scope.** [Authentication docs](https://docs.avalai.ir/fa/api-reference/authentication) describe dashboard creation, deletion/revocation, usage view, and permissions/limits, with server-only Bearer keys. They caution that model/route restrictions exist *when available* and that AvalAI has no documented OpenAI-compatible Admin API. Exact dashboard controls, default scopes and revocation propagation remain account checks. **Verified provider rule H / unresolved account behavior**.
- **Provider privacy.** The [Persian policy](https://docs.avalai.ir/fa/safety/privacy-policy) says AvalAI does not collect/store/use API request-body content and retains API call history such as model and IP for billing/safety. Its same page discusses opt-in model improvement for assistant chats (default off), third-party sharing where permitted, and a 30-day post-deletion improvement-use reservation that does not clearly separate chat from API. The [data-controls guide](https://docs.avalai.ir/fa/guides/data-controls) explicitly says upstream processing, abuse logs, application state, retention, region and ZDR depend on the exact route/provider/account. Thus **no end-to-end zero-retention, no-training, deletion time, or residency guarantee is verified**. The [older website privacy page](https://avalai.ir/privacy-policy/) is less specific and conflicts in wording with the newer documentation. **Provider statements H; complete handling unresolved**.
- **Direct Cloudflare privacy, if Architect broadens scope.** Cloudflare's [Workers AI data-use statement](https://developers.cloudflare.com/workers-ai/platform/data-usage/) says the customer owns prompts, outputs and embeddings, and Cloudflare does not use them to train models or improve services without explicit consent. It says content *may* be stored when a storage service is used with Workers AI. This is stronger published use-purpose detail than the unresolved AvalAI upstream chain, but it is **not** a no-retention, location, deletion-period, or model-licence commitment for OmniDoc. Direct Cloudflare also entails separate account, terms, key and adapter review. **H** published statement / **unresolved** operational terms.

### Verified technical facts

- [Spring AI 2.0.1 OpenAI embeddings documentation](https://docs.spring.io/spring-ai/reference/api/embeddings/openai-embeddings.html) exposes embedding-specific base URL/API key/model/encoding/dimensions options and runtime request options. It uses the official `openai-java` SDK under the hood. **Inference:** the OpenAI-shaped AvalAI text-embedding route should fit an adapter-only Spring AI client, but the base URL's `/v1` joining, response parsing, retries, and actual model route need an opt-in compatibility smoke. Spring AI types must remain in the adapter; its vector store must not own OmniDoc's corpus.
- [OpenAI's embedding guide](https://developers.openai.com/api/docs/guides/embeddings) documents normalized OpenAI text vectors and shortened `text-embedding-3-*` vectors. AvalAI's [embeddings guide](https://docs.avalai.ir/en/api-reference/embeddings) says OpenAI text vectors are normalized; it does not establish normalization for the Alibaba route. Preserve the B-06 cosine metric, then check dimensions, finiteness, magnitude, and repeatability empirically. An upstream benchmark is directional evidence only.
- [Google's embedding specification](https://ai.google.dev/gemini-api/docs/embeddings) says `gemini-embedding-001` supports `RETRIEVAL_DOCUMENT` and `RETRIEVAL_QUERY`, 2048-token input and flexible output dimensions, and requires manual normalization for output dimensions below 3072. AvalAI's own [RAG example](https://docs.avalai.ir/en/api-reference/embeddings) uses the two distinct task types and 768 dimensions through `extra_body`. **Inference:** a Spring AI generic embedding request may need adapter-level provider parameters; a future probe must establish whether Spring AI passes those controls or a dedicated adapter call is necessary. Preserve `EmbeddingPort`.
- [Alibaba's official specification](https://www.alibabacloud.com/help/en/model-studio/embedding) supports 1024 dimensions and English for `text-embedding-v4`; it reports stronger retrieval performance at higher dimensions on its own benchmark. It also says `text_type` and `instruct` are only available through native DashScope, not its OpenAI-compatible API. AvalAI's exact routed input limit, dimensions pass-through and available retrieval controls are not established. Do not apply Alibaba free quotas or regional prices to an AvalAI account.
- [Cloudflare's Qwen model page](https://developers.cloudflare.com/workers-ai/models/qwen3-embedding-0.6b/) documents a direct route, OpenAI-compatible `/v1/embeddings`, and native query/document inputs with an optional instruction. [Qwen's model card](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B) reports an English retrieval benchmark for the upstream model and says omitting a query instruction reduced retrieval performance in its tests. **Inference:** exact prompt/role handling and quality of Cloudflare's compatible endpoint need a controlled route probe; Cloudflare direct price cannot be applied to AvalAI.

### Common market practices

Batching several independent texts in an `input` array, bounded retries for 429/5xx, and per-model/dimension vector separation are standard approaches and also described in [AvalAI's embedding](https://docs.avalai.ir/en/api-reference/embeddings) and [rate-limit](https://docs.avalai.ir/en/rate-limits) guidance. They are design inputs, not acceptance evidence.

### Test observations

Documentation and local source/schema were read only. **No AvalAI or Cloudflare request, authentication test, quota check, price reconciliation, benchmark, or endpoint health check was run.** AvalAI's model-detail pages for [`text-embedding-3-small`](https://docs.avalai.ir/en/models/text-embedding-3-small) and [`gemini-embedding-001`](https://docs.avalai.ir/en/models/gemini-embedding-001) incorrectly illustrate `/v1/chat/completions` for embedding models; the dedicated embedding reference is the applicable contract. This documentation defect must not be copied into the PoC.

### Inferences

At equal input volume, 1,000 chunks × 500 input tokens ≈ 500,000 tokens: published **input** charge about **$0.035** for the chosen AvalAI Alibaba v4 route, **$0.075** for AvalAI Gemini, or **$0.0059** for *direct* Cloudflare Qwen, before query embeddings, the conflicting AvalAI Gemini output charge, retries, tax, FX and package effects. These are separate catalogues and illustrative arithmetic, not a spending forecast. A few cents across this sample does not justify choosing a weaker model without measuring retrieval quality. Benchmark scores in different vendor reports and versions are **not directly comparable** or proof of quality on S-03.

## Candidate Shortlist (tradeoffs only; no architecture selection)

**Chosen B-06d probe candidate for Architect review: AvalAI `text-embedding-v4` at 1024 dimensions.** The user confirmed this Alibaba Qwen3-series route. It is listed by AvalAI for `/v1/embeddings` at $0.07 per million input tokens, and Alibaba's published English/multilingual retrieval results and 1024-dimensional default make it a plausible fit for the existing pgvector column. Request `dimensions=1024` explicitly; if AvalAI rejects the parameter or returns another dimension/model, stop and return that evidence to Architect rather than silently accepting a different shape. The [frozen B-05 `ChunkPolicy`](../../../apps/api/src/main/java/com/omnidoc/api/chunking/ChunkPolicy.java) caps chunks at 1200 **characters**, not tokens, so the conflicting 1024-versus-8192 token limit still requires a real token-bound check on fixture chunks. Validate S-03 retrieval quality and zero forbidden hits before accepting even the development probe. Gemini 001 is a documented fallback for a separate Architect selection if v4 fails; direct Cloudflare Qwen is outside this chosen provider route. `text-embedding-3-small` remains an optional baseline. **This is a specific development-probe recommendation, not a production model decision.**

## Proof-of-Concept Plan

1. **Architect disposition first.** Review the user-selected AvalAI `text-embedding-v4` / 1024-dimensional probe, choose an offline provider probe or opt-in local adapter, exact secret mechanism, model/dimension isolation and ADR-0004 disposition. Keep `mock` as default; no new runtime mode, no fallback. Implementation is outside Researcher ownership.
2. **Version the evaluation set before the first live request.** Implementer records an immutable `s-03-v1`-derived B-06d query/relevance file (e.g. `b06d-s03-v1`) under an Architect-approved Implementer path. Use only checked-in synthetic S-03 passages, canonical IDs/chunk text and at least 12 human-judged English paraphrase queries: launch Tuesday, competing Thursday, indexing-ready, pgvector/BYOK formatting, plus ambiguity/no-match cases. Label relevant note/chunk IDs, workspace and tenant; exclude real notes. Add synthetic inaccessible/deleted/stale-version negatives where the S-03 fixture state permits, and record any missing case for B-07's wider §7 corpus. Freeze query text, labels, chunker version, and `topK` for reuse unchanged in B-07. Architect must pre-register the minimum Recall@1/3, MRR and core-query criteria before the first live response; zero forbidden hits is non-negotiable. A no-match query is a diagnostic; Recall@K is computed only where relevance exists.
3. **Run the bounded opt-in v4 probe.** Check every frozen fixture chunk against the routed token cap before submission; reject over-limit inputs rather than truncate them silently. Embed that fixture corpus and its queries once with the exact `text-embedding-v4` ID and 1024-dimensional request; collect request count, input tokens, returned model/dimensions, non-secret request IDs, observed failures/latency, and account charge. Run B-06 deterministic mock over the same corpus/query IDs. Report per-query ranks, Recall@1, Recall@3, MRR, and the difference versus mock. Tenant/workspace/ACL negative tests must yield **zero** forbidden hits. Do not present an upstream MTEB score as a project benchmark. If v4 fails, report the failure for Architect to choose whether to test a fallback; do not silently change models.
4. **Fail closed.** Assert query vector and stored document vectors have the same provider/model/dimensions and metric. The B-06 schema's one-vector-per-chunk key means compare candidates in separate local runs or an Architect-approved isolated store; never overwrite a mock baseline silently or mix candidate vectors. 401/403/404/429/5xx, malformed payload, depleted credit and timeout surface as explicit failures. Default unit/integration tests and CI stay offline.
5. **Post-implementation operator instructions (Implementer must issue exact commands for the approved shape):** create a dedicated development key in the AvalAI dashboard, restrict it to the embedding route/model if that dashboard permits, and place it only in the Architect-approved local environment/secret store (AvalAI documents `AVALAI_API_KEY`). Do not paste it into chat, source, `.env` in the repository, shell history, logs or CI. Start the explicit live profile/probe, send only frozen fixture requests to `/v1/embeddings` with `model=text-embedding-v4` and `dimensions=1024`, and check HTTP 200, returned model identity, vector count/finite values and exactly **1024** dimensions, usage/billing evidence, non-secret request ID if supplied, account transaction/credit delta, and expected Recall@K/ranks with zero isolation failures. An authenticated model-list response alone proves key access, **not** embedding correctness. Stop the live profile, clear the local secret, and delete/revoke the key in the dashboard when finished. If any check fails, report the failure without switching modes. [AvalAI embedding reference](https://docs.avalai.ir/en/api-reference/embeddings), [authentication](https://docs.avalai.ir/fa/api-reference/authentication), [User API](https://docs.avalai.ir/en/api-reference/user).

## Risks

Documentation drift, misleading model-page chat examples, conflicting Gemini output price, inconsistent Alibaba input limits, stale AvalAI Cloudflare alias, unspecified AvalAI upstream data handling and region, account-currency/offer ambiguity, Basic-tier 3 RPM, and pgvector's 2000-dimension limit. Public synthetic fixtures make a narrowly scoped PoC possible; they do not resolve production privacy or provider onboarding.

**Disposition to Architect: `GO_WITH_CONDITIONS` for a development-only, S-03-only PoC of AvalAI `text-embedding-v4` at 1024 dimensions.** Conditions: Architect approves probe/adapter and local-secret shape; `@user` decides account/terms/payment eligibility before any live call; Implementer verifies exact account route/model/dimensions/charge, reconciles the routed input cap, and produces the frozen evaluation set. A different model or provider requires explicit Architect disposition. **No GO for customer content, production, Ask/chat, B-08, or a live key in this Researcher slice.** Return to Commander to sequence the Architect review.
